# 能力与兼容性

本文概述 Aether Cockpit 的主要使用面。实际能力取决于版本、渠道实现、账号权限和上游服务状态；渠道清单与可用模型以正在运行的程序为准。

## 协议入口

| 协议 | 入口 | 说明 |
| --- | --- | --- |
| OpenAI Chat Completions | `POST /v1/chat/completions` | 流式、非流式与受支持的工具调用 |
| OpenAI Responses | `POST /v1/responses` | 流式事件、工具调用及受支持的状态续接 |
| Anthropic Messages | `POST /v1/messages` | 内容块、工具和流式响应 |
| Gemini API | `/v1beta/models/...` | 内容生成、流式生成、token 计数与模型列表 |

网关按渠道将请求转换为上游协议；对于协议与模型能力不匹配的渠道，个别功能可能不可用。模型列表接口用于发现当前可路由的模型，不代表所有模型对每个账号均可调用。

## 渠道与账号

项目包含订阅型渠道集成（例如 Claude、Codex、Qoder、WorkBuddy、Trae、Kiro、ZCode、CodeBuddy、Devin、Antigravity、MiniMax）及通用 API 接入（例如 OpenAI 兼容服务、Azure、Amazon Bedrock、Vertex AI、Gemini 兼容端点）。具体渠道可能需要网页登录、本机已登录客户端、OAuth、手动令牌或云服务凭证。

账号池提供标签、批量操作、状态与额度查询、凭证刷新、会话粘性、并发控制和故障转移。加密账号包用于迁移凭证；普通设置备份会剔除账号凭证。请在应用内阅读每种导入、备份及同步操作的提示。

## 路由与客户端

- 按优先级、轮转、额度情况或意图组织路由组；意图路由依赖配置的分类模型，未配置时会回退到基础策略。
- 使用虚拟模型组把一个稳定的客户端模型名映射到多个渠道，并按顺序故障转移。
- 为受支持的 Claude Code、Codex CLI、Gemini CLI、OpenCode 等客户端生成或恢复连接配置。
- 管理提示词、MCP 服务、Skills 和子代理，并发现部分客户端的本机资源。
- 启动带独立配置目录的客户端实例；隔离能力按客户端支持情况而异。

## 观测与自动化

- 查看渠道额度、请求用量、模型成本、路由结果、调用日志和健康探测。
- 配置周期任务、签到或账号唤醒；实际效果取决于渠道提供的接口与账号规则。
- 使用健康、就绪、版本和指标端点接入本机监控。
- 支持备份导入导出与 WebDAV 同步；云端同步使用者应自行评估远端存储的访问控制。
- 部分媒体请求、网络搜索和 MCP 工具依赖相应上游能力及用户自行配置的服务。

## 隐私边界

Aether Cockpit 默认只监听 `127.0.0.1`，并将运行数据写入本机数据目录。它会代表用户把请求和必要凭证发送给用户配置的上游服务；项目本身不是云代理，也不能替上游承诺数据保留或隐私行为。网络共享前必须设置网关密钥并限制来源。详情见[快速上手](QUICKSTART.md)和[安全政策](../SECURITY.md)。

## 已知限制

- 当前发布页提供 Windows x64 预编译包；macOS 桌面为预览构建（`docs/MACOS.md`），尚未签名/公证，也尚未作为正式发布支持范围。
- 第三方客户端和上游服务可能改变私有协议、OAuth、额度和模型行为，造成渠道暂时不可用。
- 部分桌面客户端的私有协议不作为上游渠道提供；客户端配置写入能力与作为网关上游是两件不同的事。
- Agent 版本检查只提供升级提示，不会替用户执行客户端安装或升级。
- 项目不提供上游账号、订阅或密钥；请遵守服务商的使用条款和适用法律。
