规范

Do / Don't来自 2026-10-30 的返工

这样做

  • 一行最多一个实心主按钮，其余描边或纯文字
  • 低频动作收进「更多」，危险项标红并加分隔线
  • 筛选只更新状态，不重建工具条（否则输入框丢焦点）
  • 数字加 tabular-nums，进度条统一「剩余」口径
  • 空态给下一步动作；错误说清哪一步失败
  • 新色值先进 tokens.css，再在别处 var()

不要这样

  • 所有按钮都用胶囊，靠颜色区分主次
  • 把构建时间、版本号放在每页标题栏
  • 在不适用的页面渲染筛选控件
  • 用 10–11px 承载正文，或用纯颜色表达状态
  • 给整个 #app 加 aria-live
  • 在 CSS 里直接写 #hex（lint 会拦）

可访问性

AA由 scripts/ui-audit.mjs 守住
  • 正文对比度 ≥ 4.5:1；当前最低 4.68:1（三级灰压在灰底上），标题 16.7:1。
  • 焦点环 2px 品牌蓝 + 2px 偏移，键盘可见、鼠标不打扰。Tab 第一站是「跳到主内容」。
  • 图标按钮必须有 aria-label；表单控件必须有标签（label / aria-label）。
  • 浮层：role="dialog" + 焦点陷阱 + Esc 关闭 + 关闭后焦点归位。
  • 只用一个 #status 播报点，不把整页设成 live region。
  • prefers-reduced-motion 下所有动画归零。

焦点环用 :focus-visible，不要 outline: none。
校验方式：npm run ui:lint（色值只允许在 tokens.css）、npm run ui:audit（对比度 / 溢出 / 命名 / 焦点）、npm run ui-check（冒烟）。 文档与产品共用同一份 CSS；若这里显示正常而产品不正常，说明产品页面写了局部覆盖。
